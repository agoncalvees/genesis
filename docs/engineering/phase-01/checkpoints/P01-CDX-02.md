# P01-CDX-02 — Preset Vercel

Plano: fixar Nitro, configurar o preset no Vite, inspecionar a saída Vercel e rodar as verificações locais.

Escopo: package.json, bun.lock, vite.config.ts, vercel.json e este checkpoint. O .gitignore já cobre .vercel/ e .output/.

Aceite: instalação congelada, build Vercel para Node, bundle público sem OPENROUTER, check, typecheck, unit e E2E.

## Configuração

Nitro ficou fixado em `3.0.260610-beta` (MIT), como no preset oficial identificado na matriz da fase 00. Os guias atuais instruem instalar `nitro` sem fixar outra versão. O registro confirma o peer de Vite `^7 || ^8` e Node `^20.19.0 || >=22.12.0`. O teste local usou Vite 8.3.8, Node 24.22.3 e Bun 1.4.5. [Preset oficial empacotado](https://registry.npmjs.org/@tanstack/create/-/create-0.71.15.tgz), [metadados de Nitro](https://registry.npmjs.org/nitro/3.0.260610-beta).

`vite.config.ts` registra Nitro entre TanStack Start e React e seleciona explicitamente `vercel` para o build local. `vercel.json` declara o framework `tanstack-start` conforme o template oficial. [Hosting do TanStack Start](https://tanstack.com/start/latest/docs/framework/react/guide/hosting), [guia da Vercel](https://vercel.com/kb/guide/deploy-a-tanstack-start-app-to-vercel).

## Artefato inspecionado

```text
.vercel/output/
├── config.json
├── nitro.json
├── functions/
│   └── __server.func/
│       ├── .vc-config.json
│       ├── index.mjs
│       ├── _chunks/
│       ├── _libs/
│       └── _ssr/
└── static/
    ├── assets/
    ├── fonts/
    └── textures/
```

`.vc-config.json` declara `runtime: "nodejs24.x"`, `launcherType: "Nodejs"`, `handler: "index.mjs"` e `supportsResponseStreaming: true`. O `config.json` usa a versão 3 da Build Output API e encaminha as rotas restantes para `/__server` após consultar os arquivos estáticos. O handler compilado foi importado diretamente no Node. O ensaio final retornou HTTP 200 com HTML e os textos esperados em `/` e `/smoke` (saída 0). Uma primeira sondagem retornou ambos os status 200, mas falhou por usar textos esperados incorretos antes de consultar as asserções do smoke E2E.

Autorrevisão do diff, lockfile e saída gerada concluída. Revisão independente do preset indisponível neste despacho. A validação em infraestrutura Vercel fica para um deploy autorizado.
